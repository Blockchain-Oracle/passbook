# @strk20/site — the landing page and the documentation

One site, one domain, two halves:

- `/` — the landing page
- `/docs/*` — the documentation: sidebar, table of contents, full-text search

**This is not the app.** It is its own package with its own build and its own deploy. `apps/web`
is untouched by it, and nothing in `apps/web` imports from here. The one link that leaves this site
is "Open the app".

```bash
pnpm --filter @strk20/site dev        # localhost:5231
pnpm --filter @strk20/site build
pnpm --filter @strk20/site typecheck
```

## What it is built on

[Fumadocs](https://fumadocs.dev) on Next.js (App Router), generated by `create-fumadocs-app` and
kept to its documented shape: `source.config` in `lib/source.ts`, MDX under `content/docs/`, the
docs layout at `app/docs/`, search served by `app/api/search`. The landing page is `app/(home)`
with its own chrome (`landing/`), not a docs page with a hero on it.

## What it reads rather than repeats

Every fact that could go stale is a component or a derived constant, never prose:

- `data/deployment.ts` reads `evidence/*.json` — the files the deploys wrote — so the mainnet
  record and the "deployed / not deployed" rows change when the evidence does.
- `data/surfaces.ts` keys off `@strk20/protocol`'s closed surface list; a seventh surface is a
  compile error here, not a row the site never heard of.
- `<RefusedClaims/>` renders `FORBIDDEN_CLAIMS`, the list the protocol's copy is held to.

## Writing documentation

MDX files under `content/docs/`. Each folder's `meta.json` titles it and orders its pages; the
top-level `content/docs/meta.json` orders the sections. Adding a page is adding a file.
